## Why the gateway moved off 8080

Port 8080 on this host is held by `orbisar-standalone-sar-mlops-1`
(compose project `orbisar-standalone`), which publishes `0.0.0.0:8080` and
serves uvicorn. It answers HTTP 200 on `/`, so NemoClaw does **not**
report a port conflict — it reports:

```
h2 protocol error … GoAway(FRAME_SIZE_ERROR)
Authentication: Unverified (gRPC health check failed)
```

If you meet `FRAME_SIZE_ERROR`, check who owns the port before suspecting
a version mismatch. `NEMOCLAW_GATEWAY_PORT` is the supported override
(`DEFAULT_GATEWAY_PORT = 8080` in `src/lib/core/ports.ts`).

Moving an **existing** sandbox to a non-default port requires three state
files to agree, or each layer fails in turn:

1. `~/.nemoclaw/sandboxes.json` — both `gatewayPort: 18080` **and**
   `gatewayName: "nemoclaw-18080"`. The name is derived from the port by
   `resolveGatewayName()`: default port → `nemoclaw`, anything else →
   `nemoclaw-<port>`. A mismatch gives
   `sandbox "…" has conflicting gateway identity`.
2. `~/.nemoclaw/onboard-session.json` — `metadata.gatewayName` must match,
   or you get `onboard-session.json conflicts with its sandbox registry row`.
3. Only then does the CLI migrate state into `~/.nemoclaw/gateways/18080/`.

## Why the sandbox had to be rebuilt

A sandbox built by OpenShell 0.0.44 **cannot run against a 0.0.106
gateway**. The sandbox-token contract changed; the container crash-loops
with:

```
Policy fetch failed after 5 attempts: no sandbox token source available —
set one of OPENSHELL_SANDBOX_TOKEN, OPENSHELL_SANDBOX_TOKEN_FILE, …
```

There is no in-place fix. Two traps on the way out:

- **`rebuild` fails preflight on legacy registry rows** with
  `recorded custom Dockerfile is invalid / legacy registry entry cannot
  distinguish a managed image from a custom --from image`. It aborts
  safely, touching nothing. The authorization escape hatch is
  `NEMOCLAW_CONFIRMED_LEGACY_MANAGED_SANDBOXES='["ansa-assistant"]'`, read
  only by `nemoclaw upgrade-sandboxes` — there is no `rebuild` flag for it.
- **`destroy` fails closed** on pre-0.0.44 containers
  (`the managed container is missing openshell.ai/sandbox-workspace`). It
  still clears the registry row, leaving the container orphaned; remove it
  with `docker rm -f <id>` after backing up.

A dead sandbox can still be backed up — `docker cp` works on stopped
containers:

```bash
docker cp <container>:/sandbox/.openclaw  ~/.nemoclaw/manual-backups/<name>/
```

## Base-image pinning: `.version` is obsolete

Onboard fails at **[6/8] Creating sandbox** with:

```
managed image catalog 'v0.0.114-1-gc766f9716' is unavailable:
GHCR manifest request returned HTTP 404
```

Because HEAD sits one commit past the tag (the custom Gemma 4 31B /
Opus 4.7 commit), `git describe` yields `0.0.114-1-g…`, and GHCR has no
image published under that string. `getVersion()` resolves in this order:

1. **`dist/build-identity.json`** ← wins
2. `git describe --tags --match "v*"` ← was producing the 404
3. `.version` file ← **only consulted if git describe fails, so writing
   `.version` no longer does anything**
4. `package.json`

**Fix**: set `nemoclawVersion` in `dist/build-identity.json` to the bare
release (`"0.0.114"`), leaving `sourceRevision` at the true commit hash.
The validator only cross-checks the hash when the version carries a
`-N-g<sha>` suffix, so a plain version passes cleanly.

`dist/` is regenerated by `npm install`, so **re-apply this after every
CLI rebuild**.

## Post-rebuild restore checklist

The rebuild's own backup covers agents, extensions, workspace, skills,
hooks, canvas, cron, memory, telegram, credentials and `openclaw.json`.
These three live outside it and must be redone every time:

```bash
export NEMOCLAW_GATEWAY_PORT=18080

# 1. Reattach the AVIS network (new container UUID each rebuild)
docker network connect ansa-voice-intelligence-system_default \
  $(docker ps --format '{{.Names}}' | grep -E '^openshell-.*ansa-assistant')

# 2. Reinstall mcporter (lives in /sandbox/.npm-global, outside the backup)
nemoclaw ansa-assistant exec --timeout 700 -- \
  bash -lc 'npm install -g --prefix=/sandbox/.npm-global mcporter'

# 3. Re-register AVIS, then confirm 87 tools
nemoclaw ansa-assistant exec -- bash -lc \
  'cd /sandbox/.openclaw/workspace && \
   /sandbox/.npm-global/bin/mcporter config add avis http://avis-mcp:8091/mcp'
nemoclaw ansa-assistant exec -- bash -lc \
  '/sandbox/.npm-global/bin/mcporter list avis'
```

Re-onboarding also does **not** restore user-added policies — it applies
only the default tier. Re-add each with
`nemoclaw ansa-assistant policy add <preset> --yes`. The custom presets
live in `~/NemoClaw/nemoclaw-blueprint/policies/presets/`: `avis`,
`avis-mcp`, `asias-direct`, `mandate-direct`, `nvidia-api`,
`ollama-inference`.

Workspace files must be re-uploaded too — see
[04-runbook.md §11](./04-runbook.md).

## v0.0.114 behaviour changes

- **Container naming**: `openshell-default--<name>-<uuid>` (doubled dash,
  `default` namespace), was `openshell-<name>-<uuid>`.
- **Per-port state layout**: `~/.nemoclaw/gateways/<port>/`.
- **`channels add` does not rebuild** — it stores credentials, registers
  the bridge, and prints `Change queued. Run 'nemoclaw <name> rebuild' to
  apply`. It rejects `--yes`; valid flags are `--dry-run` and `--force`.
- **`NPM_CONFIG_PREFIX` is no longer injected** into the sandbox.
- **`upload` takes a destination DIRECTORY, not a filename** — a full file
  path makes it `mkdir` that path.
- **`inference set` verification is too impatient for large models.** Use
  `--no-verify` after confirming the route with a direct `curl`.
- Cosmetic errors, all harmless: `shields.getShieldsPosture is not a
  function` (status/doctor), `inspectMutableConfigPerms is not a function`
  (after every `exec`), `repairMutableConfigPerms is not a function`
  (end of rebuild). None are fixed upstream in v0.0.114.

## Naming collision: Sentinel's "NemoClaw" is a different system

Sentinel's `nemoclaw_endpoint`
(`sentinel/crates/sentinel-agents/src/reasoning.rs`) refers to an
**on-premise, OpenAI-compatible LLM serving platform** running
`meta-llama/Llama-4-Scout-17B-16E` and `…-Maverick-17B-128E`, defaulting
to `http://llm-cluster.sentinel.local:8080/v1`.

That is **not** this NemoClaw. Ours is NVIDIA's agent-sandbox CLI; the
gateway on 18080 speaks gRPC control-plane traffic and does not serve
`/v1/chat/completions`. Pointing `SENTINEL_REASONING_URL` at it would
break Sentinel's reasoning path rather than enable it.

Sentinel's reasoning is currently disabled on purpose:
`SENTINEL_REASONING_BASE_URL=http://127.0.0.1:9` (port 9 = discard), with
the compose file noting that an unreachable default makes escalations fall
back to the calibrated score.

No AnSA service consumes NemoClaw's connection details. AVIS's only
runtime mention of the name is the string `"nemoclaw-direct"`, stamped as
a provenance label on outbound PTZ, recording and retask commands. Traffic
runs NemoClaw → AVIS, never the reverse.
